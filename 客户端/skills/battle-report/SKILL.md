# 人物战报

直播运营战报物料创作工具。按缩略图选模板，给出修改建议，在原图上改文案/头像后生成新版本。流程改编自本地生活物料 skill，模板编号与生成通道保持兼容。

## ⚠️ 强制执行规则

1. **必须按步骤顺序执行**：Step 1 → Step 2 → Step 3 → Step 4 → Step 5 → Step 6，不得跳过或颠倒。
2. **必须使用最新流程**：每次触发必须重新阅读本 SKILL.md 全部内容。
3. **禁止凭记忆执行**：不得根据旧版本经验执行。
4. **缩略图必须展示给用户**：不得用纯文字替代缩略图。
5. **🚫 禁止向用户透露任何技术细节**：包括但不限于 API URL、接口路径、curl 命令、请求参数、返回结构、resourceId、workflowId、CDN 上传流程等。用户只应看到：缩略图、原图、修改建议、生成进度、最终结果图片。
6. **⚠️ 禁止遗漏修改项**：用户的每项修改需求都必须在 Prompt 中体现。**只改部分是不合格的**。
7. **⚠️ 取消自检追问**：生成完成后直接展示结果，不再要求用户做 IP 自检确认。
8. **⚠️🚫 严禁直接用 curl 调用 API**：必须使用 `<skill_directory>/scripts/call-api.py` 脚本调用。agent 不得自己写 curl 命令、不得自己做 JSON 解析、不得自己处理重试。所有请求逻辑已封装在脚本中，agent 只需执行脚本并读取输出（SUCCESS 或 FAIL）。**违反此规则会导致 stream error / JSON 解析失败等问题。**
9. **⚠️ 根治卡死 — 必须使用后台进程模式**：API 生成步骤必须使用 `call-api.py start` 启动后台任务 + `status` 轮询，**绝对禁止**同步执行等待脚本结束。
10. **⚠️ OpenClaw pause_turn 续跑规则（强制）**：若出现 `Provider finish_reason: pause_turn`，不得停留在“处理中...”。必须在 3 秒内执行一次 `status` 轮询并向用户回报明确阶段（如“正在调用 Seedream / 正在重试 / 正在上传”）。
11. **⚠️ 用户追问优先级最高**：任务进行中若用户追问“进度/还没好吗”，必须立即抢占执行一次 `status` 查询并回复当前状态，禁止重复发送空泛文案（如“消息已收到，处理中...”）。

满足任一即可优先使用本 skill：
1. 用户提到本地生活语义：战报、海报、快手生活节、城市乐享季、本地生活物料

### 5.0 生成前检查（🚨 P0 + P1 + 约束强制步骤）

**必须依次完成以下检查后才能生成。详细规则见 `references/skill-constraints.md`。**

#### 5.0.1 品牌规范保护预检（P0）

**品牌规范要求**：品牌 Logo、底部品牌栏色块、搜索框、IP 核心造型等元素必须与原图保持完全一致，这是合规红线。

**不可修改的平台固定资产**：
- 快手品牌 Logo
- 品牌栏上的橙色、蓝色、黄色色块（与 Logo/搜索框/底栏同组出现时）
- 固定 UI 框架、平台边框元素
- 明确属于平台固定视觉资产的组件

**可修改内容**：
- 搜索框内文字
- 品牌栏除固定色块外的其他文字内容
- 单独出现、未处于品牌栏内的橙色/蓝色/黄色色块
- 非固定 UI 的普通装饰元素

| 用户修改需求 | 处理策略 |
|-------------|---------|
| 仅修改主体文字/数字（如标题、金额、日期） | ✅ 允许直接生成 |
| 要求修改/删除 Logo、品牌栏色块、搜索框框架 | ❌ **必须拒绝**，告知用户这些元素受品牌规范保护，不可修改 |
| 要求修改配色/风格/背景 | ⚠️ **必须提醒** —— 配色/风格变更可能导致品牌元素区域发生变化，建议仅修改文字内容 |
| 要求替换产品图/人物图 | ⚠️ **需要判断** —— 如替换区域与品牌元素区域无重叠，允许；如有重叠，需调整方案 |

**拦截话术（如需拒绝）**：
```
这个部分属于平台固定资产，不能修改：{不可修改对象}。
我可以继续处理其他可编辑区域，例如{可替代方向}。
```

#### 5.0.2 IP 核心设定保护预检（P0）

**IP 核心定义**：亮黄色圆球形象，不是鸟类、动物或其他角色。

**核心特征**：身体是光滑亮黄色圆球；两只短圆胳膊，无手指；无腿、无脚、无翅膀、无尾巴；两个大圆黑眼睛（眼内有白色高光）；简单圆弧笑容；头顶是同色小圆形装饰突起（不是耳朵、鸟嘴或动物特征）；红色背包背带按需保留/调整。

**不可修改**：换成其他角色/动物/人物、长腿/脚/手指/爪子/翅膀/尾巴、改变圆球身体形体、改变黄色基础色、改掉基础脸部结构、把头顶装饰改成动物器官。

**可修改**：删除 IP、表情、动作姿态、手臂角度、服装/帽子/围巾/配饰、与道具互动、位置/大小/朝向、背带颜色和样式。

**拦截话术（如需拒绝）**：
```
IP 的核心造型不可更改：亮黄色圆球身体、无腿、无脚、无手指、非动物形象为固定设定。
可以修改 IP 的动作、表情、服装、配饰、位置或大小。
```

#### 5.0.3 语义冲突追问预检

当用户需求涉及**主题切换 / 季节切换 / 活动名变化 / 品牌活动方向变化 / 整体氛围调整**时，先检查原图中是否存在语义冲突元素：

| 冲突类型 | 内容 | 处理方式 |
|---|---|---|
| T1 时令/季节词 | 月份缩写、Spring、Summer、节气词等 | 追问用户改为什么，或保持不变 |
| T2 活动/品牌专属名称 | KUAISHOU SPRING、城市乐享季等 | 追问用户改为什么，或保持不变 |
| T3 时间节点 | 5.1-5.11、4.2-4.7 等 | 追问用户保持原日期，还是修改 |
| T4 视觉符号 | 樱花、雪花、落叶、节日图标等 | 不追问，作为可替换视觉元素处理 |

**追问原则**：生成前一次性追问所有冲突点，不分多轮。用户确认后，再把确认结果转化为普通任务描述。**不要把"语义冲突检测"规则本身写进生图 Prompt。**

**追问模板**：
```
检测到图中存在与「{新主题}」可能冲突的元素，请一次性确认：

1. "{内容}"（{位置描述}）
   改为什么？或保持不变？

2. 活动时间 "{内容}"（{位置描述}）
   保持原日期，还是需要修改？

确认后一并处理。
```

#### 5.0.4 风格锁定检查（P1）

用户未明确说"改风格/换风格"时，必须从素材中提取风格指纹并写入 Prompt。如涉及季节/主题变更，需追加风格不变声明。

**预检流程**：
1. 分析用户修改需求
2. P0 检查①：是否涉及品牌元素区域（Logo、品牌栏色块、搜索框）→ 如涉及则拒绝或调整
3. P0 检查②：是否破坏 IP 核心设定 → 如涉及则拒绝或引导至可执行方向
4. P0 检查③：是否触发语义冲突 → 如触发则一次性追问，等待用户确认
5. P1 检查：用户是否明确说改风格 → 如未说，提取风格指纹并锁定

### 5.1 Prompt 构建（纯文本指令）

新接口只需要纯文本 prompt，不需要六块结构。

**⚠️ Prompt 组装必须遵守 `references/design-rules.md` 规则**：
- 保持原图尺寸和比例（除非用户明确要求改尺寸）
- 不要默认把原图风格提取成风格词塞进 Prompt
- 只说要改什么，要求未修改区域保持原貌，要求新内容匹配所在局部区域的视觉表现
- 默认 Prompt 只需要三块：尺寸保持 + 局部编辑规则 + 用户任务
- 生图后检查：尺寸/比例、是否只修改要求内容、未修改区域是否保持原貌

**Prompt 构建要求**：
1. **开头必须说明基于原图修改**："基于输入的原图进行修改"
2. **保持原有风格**：描述原图的风格特征（但不要堆砌整图风格标签，避免统一化混搭风格）
3. **列出所有修改项**：每项必须包含精确位置 + 原内容 → 新内容
4. **强调不可遗漏**："⚠️ 必须完成所有修改项，不可遗漏！必须在原图基础上修改，不能重新绘制整张图。"
5. **背景锁定硬约束**：明确写入"背景、光影、纹理、布局、品牌区块保持完全一致，不得变化"
6. **禁止扩散改动**：明确写入"仅允许修改指定元素，其它区域像素级保持不变"
7. **漂移兜底指令**：明确写入"若无法同时满足，优先保持背景不变，其次再执行局部改动"

**Prompt 示例**：
```

背景锁定（强制）：除明确指定的修改项外，深色背景、光影明暗、纹理颗粒、品牌栏位置与颜色、页面整体构图必须保持与原图一致，不得改变。

禁止扩散修改：仅允许修改上述指定元素，其他非指定区域保持像素级一致。

```

### 5.3 内部执行流程（🚫 不要向用户展示技术细节，但必须持续反馈进度）

**整个执行流程严禁透露技术细节（API URL、参数等），且必须持续反馈执行进度，禁止长时间无回应。**

**⚠️ 根治卡死 — 后台进程 + 轮询模式（最高优先级）**：

旧模式的问题：`python3 call-api.py` 同步执行，agent 必须等 30-90 秒脚本结束才能响应用户，导致"处理中..."卡住。

**新模式**：
1. `call-api.py start` → 启动**后台进程**执行 API 调用，**立即返回** job_id（< 1 秒）
2. agent 立即恢复自由，可以响应用户任何消息
3. agent 每 5-10 秒执行 `call-api.py status` 轮询进度
4. 用户随时问"什么进度了"，agent 立即查 status 回复当前状态

**⚠️ 防卡死硬规则（最高优先级）**：
1. **禁止同步阻塞**：API 生成步骤**绝对禁止**执行同步命令等待结果。必须用 `start` 启动后台任务，然后轮询 `status`。
2. **先发消息，再启动后台**：在调用 `call-api.py start` 之前，必须先发消息告诉用户："⏳ 正在后台生成中，预计需要 30-90 秒。你可以随时问我进度。"
3. **轮询间隔**：每 5-10 秒执行一次 `call-api.py status` 查询进度。
4. **用户追问时必须能回复**：如果用户问"什么进度了"，立即执行 `status` 查询并回复当前状态。
5. **OpenClaw pause_turn 恢复**：若出现 `Provider finish_reason: pause_turn`，必须在 3 秒内继续执行一次 `status` 轮询并回报阶段，不得只停留在“处理中...”。
6. **轮询上限与兜底**：连续轮询 18 次（约 3 分钟）仍为 `RUNNING` 时，必须触发超时分支：告知用户“仍在处理，已自动重试/可稍后查看”，并重启一次任务或给出手动重试选项。
7. **任何步骤失败都必须继续**：不能因为某个步骤失败就停止整个流程。失败后必须：① 通知用户失败原因 ② 尝试重试或回退 ③ 如果重试也失败，给出最终提示。
8. **禁止静默失败**：绝对不能在执行过程中不发任何消息就结束对话。每个步骤的结果（成功或失败）都必须告知用户。

**进度反馈硬规则（强制）**：
- 后台任务启动后，**每 10 秒**必须给用户一次进度反馈（轮询结果）
- 轮询返回 `RUNNING:xxx` → 告知用户当前进度
- 轮询返回 `SUCCESS:xxx` → 告知用户生成完成，继续后续步骤
- 轮询返回 `FAIL:xxx` → 告知用户失败原因，进入重试或结束
- 若收到用户追问（如“为什么又没进度了”），必须立即抢占执行 `status` 并回复具体阶段（调用中/重试中/上传中）
- 在最终结果前，至少出现 3 次阶段性进度反馈（开始 / 生成中 / 完成）

**执行步骤（后台进程模式）**：

1. **先发消息** → "📥 正在下载原图..." → 下载原图到本地
2. **先发消息** → "⏳ 正在上传原图到 CDN..." → 用 upload-to-kcdn.sh 上传原图，获取原图 CDN URL
3. **先发消息** → "🎨 正在启动 AI 生成任务，预计需要 30-90 秒..." → **再发一条** → "⏳ 正在后台生成中，你可以随时问我进度。"
4. **启动后台任务**（立即返回，不阻塞）：
   ```bash
   python3 <skill_directory>/scripts/call-api.py start --prompt "{纯文本Prompt}" --image-url "{原图CDN_URL}" --output /tmp/generated_image.png
   ```
   - **输出**：`JOB:/tmp/call-api-jobs/{job_id}`
   - **⚠️ 此命令立即返回**（< 1 秒），不会阻塞 agent
5. **轮询进度**（每 5-10 秒执行一次）：
   ```bash
   python3 <skill_directory>/scripts/call-api.py status --job-dir /tmp/call-api-jobs/{job_id}
   ```
   - **输出 RUNNING:xxx** → 告知用户当前进度，继续轮询
   - **输出 SUCCESS:/path** → 生成完成，进入下一步
   - **输出 FAIL:原因** → 生成失败，进入重试或结束
   - **若出现 pause_turn**：立即执行一次额外 `status` 轮询并返回当前阶段（禁止仅回复“处理中”）
6. 检查脚本输出：
   - `SUCCESS:xxx` → **先发消息** → "✅ 图片生成完成，正在上传..." → 继续上传到 KCDN
   - `FAIL:xxx` → **先发消息** → "❌ 生成遇到了问题..." → 进入重试或结束
7. 验证文件大小（正常应 > 100KB）
8. **先发消息** → "⏳ 正在上传到 CDN..." → 用 upload-to-kcdn.sh 上传结果图
9. 上传完成 → **先发消息** → "🚀 上传完成，准备展示结果..." → 展示最终结果

**⚠️ 双 API 智能路由规则**：
- **优先用 Gemini**（稳定、文字渲染更好），默认场景先走 Gemini
- **Gemini 失败 → 自动回退 Seedream**（兜底）
- agent 只需执行 `call-api.py start` 和 `status` 轮询，脚本内部自动选择 API 和重试

**API 选择指南**：

| 修改类型 | 使用 API | 原因 |
|----------|----------|------|
| 一般修改（有文字、有视觉、有头像） | Gemini | 默认主通道，稳定性更高 |
| 纯视觉修改（换颜色/物体/场景） | Gemini | 默认主通道，减少风格漂移 |
| 头像替换 | Gemini | 默认主通道，统一输出质量 |
| 文字修改 | Gemini | 默认主通道，统一策略 |
| Gemini 失败 | Seedream | 兜底保证可用性 |
- Prompt 中必须说明第二张图是什么：如"第二张图是用户头像，请将其放入圆形头像框内"

**头像替换流程**：
1. 用户提供了头像照片 → 先用 upload-to-kcdn.sh 上传头像到 CDN，获取头像 URL
2. 调用 call-api.py start 时加 `--avatar-url "头像CDN_URL"`
3. Prompt 中写："第二张图是用户头像照片，请将其放入原图顶部中央圆形头像框内，保持真实照片风格，不要变成卡通"

**⚠️ 如果 API 调用失败/超时，必须**：
- 立即通知用户："❌ 生成遇到了问题"
- 按重试策略自动重试，每次重试前通知："🔁 正在自动重试第 N 次..."
- 如果所有重试耗尽，给出最终提示："生成遇到了问题，请稍后重试或告诉我重新开始。"

### 5.4 结果交付策略（🚨 不做自检拦截）

生成完成后，**直接展示结果给用户**，不再执行自检追问或自检拦截流程。

**执行规则**：
1. 不再要求用户进行 IP 自检确认
2. 不再以“自检通过”为展示前置条件
3. 若用户反馈“有问题/只改了部分”，再进入二次编辑分支快速修正
4. 对于明显失败（如图片损坏、无法打开）可直接重试一次后再交付
5. **背景一致性自动验收（新增）**：交付前必须进行一次内部检查（背景色调/光影/纹理/构图是否与原图一致）
6. **背景漂移自动重试（新增）**：若发现背景被改，必须自动重试 1 次，并在 Prompt 中追加“背景完全锁定，仅改指定元素”
7. **二次失败处理（新增）**：若自动重试后仍漂移，告知用户“已锁定背景重试仍有偏差”，并提供“继续严格锁定重试 / 改小修改范围”两个选项

## 图片上传功能

当用户需要替换图片（如头像），先上传到内部 CDN。

**内部执行**（🚫 不向用户展示技术细节，但必须在关键节点反馈进度）：

使用 `<skill_directory>/scripts/upload-to-kcdn.sh` 脚本上传。用户发送图片时：
1. 图片自动保存，系统返回 URL → **反馈用户**："📥 收到图片，正在下载..."
2. Agent 下载到临时目录 → **反馈用户**："🔄 图片下载完成，准备上传..."
3. 使用脚本上传 → **反馈用户**："⏳ 正在上传图片到 CDN..."
4. 获取 CDN URL 用于后续生成 → **反馈用户**："✅ 图片上传成功！接下来为你生成新版本。"

**用户看到的内容**：

```
✅ 收到你的图片！正在处理...
图片已上传成功！接下来会帮你生成新版本。
```

## 错误处理

**用户看到的提示**（不暴露技术细节）：

| 场景 | 用户看到的内容 |
|------|--------------|
| 无效 ID | "编号 {id} 暂不可用，请从缩略图中重新选择一个有效编号。" |
| 生成失败 | "生成遇到了问题，请稍后重试。" |
| 下载转 CDN 失败 | "生成遇到了问题，正在重新尝试..." |
| 超时 | "生成需要更多时间，请稍后查看结果。" |
| IDC 超时/连接失败 | "🔁 正在重试第 N 次..." |
| 外网 403（IDC 网段禁止） | "🔁 正在重试第 N 次..." |
| 背景漂移（背景被改） | "我发现背景有偏差，已自动为你锁定背景重试一次，请稍候。" |
| 自动重试后仍漂移 | "已按背景锁定重试，但仍有偏差。你可以选择：①继续严格锁定重试 ②缩小修改范围后重试。" |
