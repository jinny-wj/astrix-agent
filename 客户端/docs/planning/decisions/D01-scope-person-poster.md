# 只做 #1 人物海报批量延展

**决策时间**：#R3
**状态**：✅ 已确认
**关联大纲**：[返回大纲](../outline.md)

## 📋 背景

### 问题/需求
用户希望「复刻码灵（M0 Design）」，参考文档《【AI探索专项】直播运营设计&码灵批量自动化解决方案》中提出了四条 AI 机会点。需要确定首轮攻坚范围。

### 约束条件
- 用户自我定位为视觉设计（人物海报、资源位），不做 UI 设计
- M0 Design 为快手内网平台，本地复刻必须替换底层生成 runtime
- 本地 dreamina 账户仅 80 credits，不足以支撑批量

---

## 🎯 目标

选出一条能最快验证「本地能否复刻码灵核心能力」的场景，避免多线并行导致栈分散。

---

## 📊 方案对比

| 方案 | 描述 | 优势 | 劣势 | 决策 |
|------|------|------|------|------|
| #1 人物海报批量延展 | 主播照片 → 修图 → 套模板 → 换信息 → 批量导出 | 文档口径收益最大（40x、年省24-36万）；最独立不依赖 H5/Figma 生态；能验证最大未知（AI 修图质量） | 强依赖图像模型；存在「不能改脸」的一票否决风险 | ✅ |
| #2 线上资源位延展 | KV → 多规格重排 → 导出 Figma 可编辑文件 | 本质是程序题，确定性高；Figma 写入链路已具备 | 收益低于 #1（4x）；需要 KV 分层源文件 | ❌ 后置 |
| #3 BC级 KV 换色 + UI 适配 | H5 换肤换色 | — | 涉及 UI 页面结构，与用户「不做 UI」定位冲突 | ❌ 后置 |
| #4 长图配置工具 | JSON 模板 + 文档文案 → 长图 | 纯程序题，最快见效 | 不涉及 AI 能力，无法验证复刻可行性 | ❌ 后置 |
| #1 + #2 并行 | 同时推进两条 P0 | 覆盖面广 | 两条栈几乎不重叠（图像模型 vs 版式引擎），会互相拖累 | ❌ |

---

## ✅ 最终决策

### 选定方案
本轮只做 **#1 人物海报批量延展**，其余三条全部后置。

### 决策理由
1. 收益最大且量化清晰，便于事后验证复刻成效
2. 链路最独立，不依赖 Figma / H5 / 积木配置等外部生态
3. 承载了整件事最大的未知：**AI 人像修图能否在不改脸的前提下达到可交付质量**。这个问题必须先回答，否则后续所有规划都是空中楼阁
4. #1 跑通后，其中「模板套用 + 信息替换 + 批量导出 + 自动质检」约一半能力可直接迁移到 #2

### 预期效果
产出一条可跑通的本地流水线：素材文件夹 + 信息表 → 批量人物海报成品 + 质检报告。

---

## ❌ 被否决的方案

### #1 与 #2 并行
- **否决原因**：#1 的核心是图像模型能力（抠图、修图、人像融合），#2 的核心是版式引擎能力（元素分层、响应式重排、Figma 写入），技术栈几乎不重叠。并行会导致两边都做不深。
- **重新考虑条件**：#1 流水线跑通并稳定后，立即启动 #2。

### #2 / #3 / #4 单独优先
- **否决原因**：#2 收益低于 #1；#3 涉及 UI 页面结构，与用户定位冲突；#4 不涉及 AI，无法回答「本地能否复刻码灵」这一核心问题。
- **重新考虑条件**：若 #1 的人脸保真验证失败（模型无法保证不改脸），应立即转向 #2 —— 因为 #2 不吃图像模型，确定性高得多。
