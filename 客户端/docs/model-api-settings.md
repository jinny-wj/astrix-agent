# AI 模型 API 设置

入口：客户端首页右上角齿轮 → 工作台设置 → AI 模型 API。

可以先不创建或填写 API Key，直接保留入口；也可以将服务地址和模型 ID 保存为未启用的草稿。空白草稿允许保存，非空服务地址须为有效地址。

## 后续接入

1. 填入服务商提供的 OpenAI 兼容 Base URL（通常以 `/v1` 结尾）和完整模型 ID。模型 ID 中的斜杠、点等字符会原样保留。
2. 在客户端填写自己的 API Key，勾选启用，再保存。已保存的 Key 不回显；留空保留原值，「清除配置」会移除它。
3. 模型选「Auto」、服务器菜单选「自动选择」时，使用配置中的 API 和模型。手动选定 Agent 时优先使用手动选择；指定其他模型时仍沿用原有 Agent 路由。
4. 如需验证，手动点击「测试连接」。测试当前输入，不保存、不启用，并会发送少量请求，可能产生少量费用。仅保存或打开设置不会请求模型。

服务地址接受 HTTPS；本机测试还可使用 localhost、127.0.0.1 或 ::1 的 HTTP。地址不得包含账号、密码、查询参数或片段。尾部 `/chat/completions` 会自动移除，运行时统一拼接此路径，且不跟随重定向。

## 能力与保存范围

对话接口采用 [Chat Completions 的请求与响应结构](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。此入口目前用于文字对话和已提供的文字/图层上下文，不提供图片生成、直接读取本机文件或执行工具的能力。图片和二进制附件内容不会经此入口发送；已有 Figma Bridge 指令仍以实际执行回执为准。

配置保存在当前系统用户的应用数据目录，通过 Electron safeStorage 加密；没有明文回退。网页端不提供配置读写接口，桌面设置仅经受信任首页的 IPC 操作，读取结果只含地址、模型和配置状态，不返回已保存的 Key。

启用后保存和清除会即时更新后续请求，重启会重新读取配置。可选配置读取失败不会阻止客户端启动；可在设置中清除后重新填写。正在执行的请求保留开始时的配置。请求失败不会自动向其他服务重发相同内容。

## 验证范围

自动化测试使用临时加密存储和模拟模型响应，覆盖草稿、保留已有 Key、重启读取、清除、无权限来源、Auto 路由、失败、取消和超时。没有创建真实 API Key，也没有调用真实模型服务；具体服务商与模型的可用性需在用户填入配置后测试。
