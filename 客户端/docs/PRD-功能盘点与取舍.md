## 2. 当前产品结论

当前项目实际包含三条不同的产品路线，它们共享一套首页和编辑器外壳，但核心技术与目标用户并不相同。

本轮共盘点 **146 个功能项**：45 项可直接或仅本地使用、41 项部分可用、34 项界面占位、22 项未实现、3 项仅有技术底座，另有 1 项明确不适用。这里的“可用”只代表当前代码路径存在，不代表已经达到公网生产标准。

| 路线 | 核心价值 | 当前成熟度 | 建议 |
|---|---|---:|---|
| A. Figma AI 协作工作台 | 授权 Figma、读取文件、查看图层与画布、选中节点后与 Agent 协作 | 最高；读取链已真实跑通 | **建议作为当前主线** |
| B. AI 视觉稿生成器 | 输入描述，生成可编辑视觉稿，改文案、主题、构图并导出 | 中等；目前是模板与关键词规则，不是通用设计模型 | 作为 P1 模板化能力保留 |
| C. 人物海报 / 资源位批量生产 | 人像处理、模板套版、多规格导出与质检 | 低；主界面是演示，CLI 只适合小样验证 | 单独立项，不与 A 同期扩张 |

### 2.1 建议的第一版产品定义

> 一个浏览器中的 Figma AI 协作工作台：用户可以连接 Figma、读取指定文件，在本地查看图层和画布，选中节点后向 Agent 提问或发起修改，并导出结果或跳回真实 Figma。

### 2.2 当前最完整的闭环

1. 首页连接 Figma。
2. 从最近文件或链接选择一个 Figma 文件。
3. 授权后自动返回 `/editor` 并读取文件结构、图片和图层。
4. 在左侧图层树与中央画布之间同步选择节点。
5. 平移、缩放、查看文件，并可在新标签打开真实 Figma。

### 2.3 当前最需要避免的误导

- “图片生成、字体生成、图生 UI、组件搜索”等多个入口目前没有独立能力，基本都进入同一个视觉稿模板流程。
- AI 视觉稿是固定 375×830 模板，主要由关键词和正则规则改变文案、主题与构图。
- Agent 可以真实流式回复，但不能直接生成图片，也没有把当前 Figma 节点作为真实上下文发送。
- Figma 读取是只读的；本地编辑尚未覆盖真实 Figma 节点，写回 Bridge 也未接进主流程。
- 批量资源位结果和多张缩略图目前主要是固定演示数据。

## 13. 核心用户流程与验收标准

### 13.1 Figma 文件读取

1. 用户从最近文件或链接选择 Figma 文件。
2. 未授权时进入官方 OAuth；授权完成后自动返回。
3. 工作台展示加载状态。
4. 成功后左侧出现真实图层树，中央出现文件画布。
5. 点击图层或画布节点，双方选区同步。
6. 用户可以缩放、平移，并在新标签打开真实 Figma。

验收：授权往返无需第二次粘贴链接；403 / 404 / 429 / 授权过期都有可理解提示；刷新后可恢复当前文件。

### 13.2 Agent 分析当前节点

1. 用户在图层树或画布选中一个节点。
2. Agent 输入区明确显示当前上下文。
3. 发送请求时包含文件、页面、节点 ID 和必要节点摘要。
4. Agent 回复明确引用当前节点，不假装已经写回 Figma。

验收：未选节点时说明分析整个页面；选中节点后请求上下文真实变化；真实模式与演示模式始终可见。

### 13.3 模板视觉稿生成（若保留）

1. 用户在首页输入 Prompt。
2. 工作台显示生成状态并产出模板视觉稿。
3. 用户修改主副标题、主题和构图。
4. 导出 PNG / JPG 与画布可视结果一致。

验收：不再展示与结果不一致的 Web · 1440；“换图”若仍是构图切换必须改名；导出不截断正文且颜色一致。
