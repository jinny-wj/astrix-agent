# Recovered browser frontend

`node frontend-tools/prepare-frontend.mjs` creates `public/index.html`, `public/local-runtime.js`, and `public/vendor/` from the recovered static-asset allowlist. It does not read raw Chromium cache, account/session responses, or the excluded server-injected JSON. Original recovered files are unchanged. `asset-map.json` records the local paths and counts of removed embedded credential literals (no values).

The default recovery root is `../M0-AI-recovered`. When that directory contains only the restricted runtime package, prepare from a separate complete recovery directory with `node frontend-tools/prepare-frontend.mjs --source-root /path/to/M0-AI-recovered`, or set `M0_RECOVERY_ROOT` to that directory. It must contain `web-assets/cache-recovered/manifest.json`; source evidence is read-only. The existing local generator artifacts and extra assets are retained.

`branding.mjs` changes only known visible workbench literals and the original logo bindings to Astrix. The checked-in `branding/astrix-logo-v1.png` is copied from the existing Astrix brand asset and prepared under `/branding/`; titles, the default avatar and the Bridge use that brand. Storage keys, bridge message names, schema functions and original import formats retain their compatibility names. User-authored project names, messages and design text are never globally rewritten.

The local root route is patched from the recovered website's marketing `/welcome` redirect to `/home`, without defining `window.electron`. The exact one-match derivative patch is recorded in `asset-map.json`. This makes both the browser root and the local desktop open the actual recovered workbench.

The original `M0Mode` local-storage key defaults to `code` only when it has no valid existing value. A user-selected Design value is preserved. In the desktop, the Code pane hosts the recovered original KSCode editor through the clean desktop's `WebContentsView`. In the browser, or if native startup fails, it embeds the independently implemented `/__local/editor?embedded=1`. Design/Figma now mounts `/figma-workspace.html?projectId=…`: an actual Figma WebContentsView in a separate desktop session, with the official editor's own canvas, layer tree and properties. Browser mode opens Figma normally and uses the same explicit Plugin Bridge; it does not embed a read-only Figma preview or show the authored canvas as its default. The surrounding recovered project and chat UI remains in place. Embedded cloud demo records and automatic demo opening are disabled. Four absent optional material/skill icon cleanup calls are guarded to allow navigation away from Home.

`figma-workspace.html/js/css` provide project link persistence, actual page/loading status, a one-time Bridge pairing code, plugin-directory help, live session/selection summaries and bounded manual text/fill/resize/export commands. A queued command is not success: the UI polls its ID and verifies the returned file/session before showing the real plugin acknowledgement. Commands freeze file, session, selection revision and node IDs; an offline selected session is not silently replaced. Selection context crosses only the expected same-origin workspace iframe and project into the parent runtime, which attaches it to a small chat POST allowlist. The backend must independently revalidate the context and its AI write permission. See [FIGMA-WORKSPACE.md](./FIGMA-WORKSPACE.md).

The editor toolbar offers Code, an isolated local HTML Preview, and Code Tools. When native APIs are present it also exposes Terminal, the Open VSX Extensions Marketplace and Install VSIX; these wait for the native editor before invoking its explicit methods. The label reads actual `getStatus().capabilities` and marketplace status. Open VSX is enabled only in the separate native editor session/server, not in this renderer's old-service remapper. Preview uses `/__local/preview` in a sandboxed iframe with scripts but no same-origin permission; it does not execute project build scripts or preview React Native by itself. `/codegen.html` calls the recovered original KRN/theme generators through the local backend and can download or import generated text files without overwriting existing workspace files. The provenance, exact adapters and generation checks are documented in `../plugins/README.md`. Original corporate plugin autoload stays disabled: the isolated generator worker is separate from the incomplete Figma/plugin runtime.

The previous authored local design editor remains independently addressable at `/local-canvas/index.html`; its source and data are preserved, but it is no longer the recovered Design entry. Its capabilities and limitations are in `../canvas/README.md`. Route changes update the real Figma workspace's project ID and discard a previous project's chat context. The local links also expose `/__local/workflow`; the separate `workflow-monitor.js` observes real multi-agent progress on the main chat without navigating away.

The desktop contract is `m0LocalDesktop.nativeEditor.{available,show,hide,updateBounds,getStatus}`. `show` receives `{bounds:{x,y,width,height},projectId}` with CSS-pixel viewport coordinates; the renderer never sends a workspace path. The native main process resolves the current workspace from `/__local/editor-context`. Only an empty parent-renderer div with `data-m0-native-editor-host` is covered, leaving its label and toolbar outside the native bounds. Resize, scroll, project navigation, workspace selection, preview tabs and visible dialogs update or hide the view; pending initialization is checked again before displaying it.

The real Figma contract is `m0LocalDesktop.figmaHost.{available,show,hide,updateBounds,getStatus,openExternal,revealBridgePlugin,onStatus}`. The local parent owns these methods; the child workspace receives only validated status/messages. The parent adds the iframe and host rectangles to obtain CSS-pixel native bounds. Figma and Code native views are exclusive in the main process. Child dialogs explicitly suspend the Figma view; outer dialogs, hidden tabs, routing and pending navigation also hide it. The Figma page has its own session and never imports `local-runtime.js` or the recovered preload.

Corporate plugin autoload is skipped when the explicitly authored `window.__M0_LOCAL_PLUGINS__` registry is empty. Explicit imports require an entry with a same-origin URL, and unavailable plugins produce an integration notice; the project does not claim their capabilities. All compiled-bundle patches are exact-match checked, recorded in `asset-map.json`, and only affect generated files. The native preload exposes only `m0LocalDesktop`; `workspaceAPI.selectPath()` uses its native directory picker when available and the local RPC otherwise.

`node frontend-tools/recover-extra-assets.mjs [diagnostic.json ...]` optionally retrieves only static images/fonts explicitly named in the supplied UI diagnostics from `cdnfile.corp.kuaishou.com`. It sends no credentials, refuses redirects and HTML/login responses, and caps each file at 10 MiB. `extra-assets/manifest.json` records URLs, hashes and sizes; the build then rewrites these references to `/extra-assets/`. Optional marketing GIFs are skipped. These static additions are separate from recovery of server source code.

The original Vue/Vite entry is `index-8tYpB-jE.js`; the newest `/home` route loads `home-Dq22ywRR.js`. Relative ESM imports and CSS continue to use their recovered directory structure. Monaco worker URLs are rewritten to local files. The optional native desktop must keep the renderer in its browser branch: exposing `window.electron` would activate unreconstructed original native dependencies.

## Backend contracts

- `GET /rest/users/getUserInfo`: user object or `{data: user}`; do not return `authUrl`.
- `/devops-api/project/v2/{list,create,info,update,delete}` and `/devops-api/session/{list,history_message}`: the original project/session client unwraps the HTTP JSON body once.
- `/api/*` targets the old Nest service and `/design-api/*` targets missing design services. Requests to original corporate hosts and local ports are remapped to this server's same path before any network connection.
- `POST /__local/rpc`: `{method, args}`; returns either the value directly or `{result: value}`, and HTTP errors or `{error: {message}}` reject. Browser compatibility exposes `opencode.getStatus`, `opencode.clientCall`, `cli.getPorts`, workspace and app methods.
- `GET /__local/models`: public configuration `{models:[{model_id,name,enable,multimodal}]}`. Startup awaits this before importing the recovered entry, and normalizes `name` to its `display_name` field. The endpoint must never return the configured API key.
- `GET /devops-api/project/container_available`: browser health probe; `{status:200}` identifies the local service as available.
- `POST /__local/client-error`: `{message,stack,url}` only; no identity, request bodies, local storage, or page contents are submitted.
- `/__local/settings`: independently implemented local configuration page.
- `/__local/editor-context`: selected-workspace context for the original native editor.
- `/__local/editor`, `/__local/projects`, `/__local/skills`: local file editing, project/session management, and read-only recovered skill reference pages.
- `POST /__local/generate/krn` with `{schema}` and `/__local/generate/theme` with `{theme}`: isolated recovered-plugin output `{success,engine,files:[{path,content}],sourceSha256,offline,notes}`.
- `POST /__local/project/import` with `{files:[{path,content}]}`: import generated files into the selected workspace, rejecting existing paths and escapes. `GET /__local/project/export` exports a text-only project bundle.
- `GET /__local/preview` and its project-relative asset paths: a restricted HTML preview of the selected workspace; unavailable HTML receives a readable notice.
- `GET/PUT /__local/canvas?projectId=…`: project-bound authored canvas document and hash revision. PUT requires `{document,expectedRevision}`; conflicts return HTTP 409.
- `POST /__local/canvas/generate?projectId=…` with `{expectedRevision,directory,nodeId?}`: generate through the original KRN plugin from the saved canvas and import into that same project, refusing existing output paths.
- `GET/PUT /__local/figma/workspace?projectId=…`: persisted project Figma URL/fileKey; PUT `{url}`. `GET /__local/figma/metadata?projectId=…` supplies the plugin directory and local Bridge address.
- `/__local/figma/bridge/{status,selection,pair,commands,results/:id}`: owner Bridge APIs. Selection uses `revision`; commands bind it as `selectionRevision`, plus fileKey/sessionId and explicit targets. Pair codes are one-time; plugin session tokens are never returned to this workspace.

The minimal `kConf_*` globals are authored anew: one local model choice, an empty application configuration and the local origin allowlist. They are not recovered server configuration. Old service credential literals are removed from generated JS. Browser fingerprinting and watermark scripts are omitted. The recovered workbench's old network calls still stay at localhost. Only the separate, explicit real-Figma host performs the normal Figma login/navigation flow; it does not reuse the original app's accounts or corporate proxy.

The original corporate Figma patch/proxy, design cloud, corporate identity, and remote server implementations have not been recovered. The real-Figma integration is a new standard Plugin Bridge adapter; loading the official editor does not imply that all 73 original private M0 functions are supported. Original OpenCode and KSCode engines and the isolated KRN/theme transforms remain available. This is an integration project built around recovered compiled modules; it does not reconstruct the original TypeScript frontend source or missing hosted services.

Version 0.5.0 copies the canvas vector and collaboration ES modules plus the pinned `canvas/vendor/` tree during preparation, excluding test modules. No CDN is needed. `/__local/collaboration/` provides project-bound transactional operation sync and SSE; the separate, opt-in LAN gateway serves only this static canvas and invited collaboration APIs. Desktop collaboration links open constrained peer windows. See `../docs/本地实时协作.md`.
