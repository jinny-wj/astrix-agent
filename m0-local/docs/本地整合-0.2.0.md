# M0 本地整合 0.2.0

这是 0.2.0 的阶段记录。后续已补齐本地画布、多 Agent、终端与扩展，最新状态见 [0.3.0 整合说明](本地整合-0.3.0.md)。

2026-10-23。本轮在原工作台构建和已有本地服务的基础上，接入恢复包中可实际运行的组件。正常入口仍是项目根目录的 `启动M0.command` 或 `npm run desktop`；模型仍为用户选定的演示模式，未配置或调用真实外部模型。

## 已接入的原实现

| 组件 | 本地用途 | 接入位置 |
| --- | --- | --- |
| KSCode / Monaco | 桌面 Code 面板直接编辑当前项目，自动保存，随项目切换 | `desktop/original-editor.cjs`、`editor-server.cjs` |
| OpenCode 1.17.10 | 设置中可选执行引擎，连接用户配置的兼容模型，执行原文件工具循环并保留引擎会话 | `server/opencode.mjs`、`server/chat.mjs` |
| 生产 KRN 插件 | M0Schema 转 `App.tsx` / `styles.ts`，含原线性渐变转换 | `plugins/`、工作台的“代码工具” |
| 主题导出插件 | 输出 `styles.json`、`variables.json`、`variable-collection.json` | 同上 |
| 原包 64 份技能 | 搜索、阅读及导出原 `SKILL.md` | 工作台的“原版 Skills” |

原 KSCode server 在自己的子进程内，通过原 Unix socket 与嵌入视图通信；使用独立工作台数据目录，原安装 app 和恢复证据保持不变。外层网页保持隔离，原编辑器视图只加载恢复的本地代码。当前原编辑器使用随包英文 NLS；中文 NLS 尚未接通。终端和扩展宿主未启用。

OpenCode 按轮启动原二进制，模型、写入开关与工作区来自本工程配置，HOME/XDG 和会话数据库在 `.local-data/opencode-runtime`。它不会读取原客户端登录配置，不启动原公司的模型网关、MCP 或自动下载插件。文件写入默认关闭；当前未启用 shell、外部目录、联网工具和子 Agent。选择原引擎不代表外层 LangGraph 多 Agent 调度已等效恢复。

KRN 与主题插件保留原转换算法，派生构建只隔离顶层 Snack 初始化、自动联网及预览注册，并改成独立线程可调用的出口。`plugins/recovered/manifest.json` 记录原始与派生哈希、具体修改；每次运行检查派生哈希。生成的文件作为文本返回，不在生成器内执行。输入需要 M0Schema，不能把 Figma REST 文件原封不动传入。React Native / 企业组件仍需目标工程提供依赖；主题图片导出需要真实 Figma 节点，当前明确返回未接通。

## 补齐的本地操作

- 项目、会话的打开、重命名、删除及历史消息；删除项目记录保留磁盘文件。
- 文件和目录创建、重命名、回收/撤销、JSON 文本文件包导入与导出；导入不覆盖已有文件。
- Code / 预览切换。预览根目录 `index.html`，或 `dist/index.html`，可加载 CSS 和相对 ES Module；不自动执行 npm、构建或项目服务器。预览脚本不能访问父工作台及模型配置。
- 普通模型助手的真实 SSE 文本流、碎片工具参数组装及取消。任务开始时固定工作区，用户切换项目不会把进行中的工具调用转到另一目录。
- 代码工具支持示例与 JSON 文件输入、查看/复制/下载生成文件、打包导出和导入当前工作区。

这些功能的 HTTP、持久化和适配代码由本项目补写；报告分别标明原算法与新写的本地接口，没有把它们当成原服务端源码。

## 验证与复跑

`npm test` 已通过 17 项 Node 集成测试，以及原插件的 5 项转换/边界验证，完整输出在 `diagnostics/integration-tests-0.2.0.log`。原 OpenCode 测试使用本机测试模型，实际执行原 read/write 工具、继续会话、切换引擎后补齐新增历史，并经过 `/api/agent/chat` 返回 AG-UI 事件和保存历史；没有使用真实模型密钥或外部推理服务。取消验证包含在一批工具执行途中停止，确保后续写入不会继续。

代码生成界面实际完成 KRN 生成与两文件导入、主题生成与三文件导入，并打开 `App.tsx`。5 份输出文件的磁盘字节和 SHA-256 记录在 `diagnostics/codegen-ui-verification.json`，截图为 `codegen-ui.png` 和 `codegen-workspace-ui.png`。

`npm run test:preview` 使用独立 Electron 和临时本地服务，实际验证 ES Module、CSS、API 请求被隔离及父文档访问被拒绝，结果为 `diagnostics/preview-check.json`。报告中的 CSP 拒绝消息来自刻意尝试访问主应用 API 的验证步骤。

原编辑器的嵌入、键入保存、项目切换、预览/模态/页面切换和关闭生命周期由 `tools/test-native-editor-integration.cjs` 验证，16 项断言均通过，逐项状态见 `diagnostics/native-editor-integration.json`。宿主页面截图为 `diagnostics/native-editor-integrated-window.png`，原编辑器视图截图另存为 `diagnostics/native-editor-integrated-content.png`；Electron 的宿主截图未包含子 WebContentsView。该测试使用独立端口、工作区及 Electron profile，不修改正常项目。

准备新副本：

```sh
npm install
npm run prepare:frontend
npm run desktop
```

保留相邻 `M0-AI-recovered` 目录。完整的来源、反向分析记录及原制品均在该恢复包中。`npm run editor:original` 仍保留先前独立编辑器试验入口，日常编辑使用主工作台即可。

## 尚未等效恢复

Figma 在线画布及账号/文档状态、企业资产和发布、图像生成服务、外层 LangGraph 调度、原终端和扩展宿主仍未接通。原前端的这些入口不能代表背后能力已经可用。完整服务端、原始 monorepo 和没有分发到本机的代码仍未取得，因此当前是实际接入原组件的本地重建版，不能称作与 M0 AI 功能完全一样。
