# 真实 Figma 接入指南

Design 默认打开真实 Figma 工作区。桌面版在独立登录会话里加载官方 Figma 页面，使用 Figma 自带的画布、图层树、属性面板与在线协作；原 M0 的项目导航、聊天和 Code 工作区继续使用。没有把旧本地 canvas 当成 Figma，也不需要先离线恢复旧版 WASM。

这条接入由新的宿主与 Plugin Bridge 实现，不是恢复了原 M0 的企业 Figma 代理和全部私有函数。插件基于 Astrix 固定提交派生，归属与改动见 [插件来源](../figma-plugin-bridge/SOURCES.json) 和 [插件说明](../figma-plugin-bridge/README.md)。

## 1. 打开项目与真实文件

1. 运行 `npm run desktop` 或双击“启动M0.command”，创建或打开一个本地项目。
2. 切换到 **Design / Figma**。粘贴正常的 `https://www.figma.com/design/…` 文件链接，点击“打开”。没有文件链接时会进入官方文件首页。
3. 在真实 Figma 页面正常登录自己的账户，确认拥有目标文件的访问/编辑权限。每个本地项目保存自己的 Figma 文件链接。

桌面里的 Figma 登录会话与本地 M0 用户、模型配置各自独立，不读取原客户端的登录数据。网页模式不会把只读 embed 当成编辑器；点击“在 Figma 打开”，在官方文件中设计，再通过 Bridge 操作选区。

## 2. 配对目标文件的插件

1. 工作区点击 **连接 Bridge → 生成配对码**。配对码仅五分钟有效、只能使用一次。
2. 点击“插件目录”查看本机生成的路径，或“在 Finder 显示插件”。使用该目录的 `manifest.json`，它包含当前本地服务端口。
3. 在官方 **Figma Desktop → Plugins → Development → Import plugin from manifest** 导入，打开同一个目标文件，再运行 **M0 Local Figma Bridge**。
4. 在插件面板输入工作区显示的本机服务地址和一次性配对码。
5. 回到 M0，确认 **Bridge 已连接**，并在 Figma 中选择一个或多个图层。底部应显示匹配的图层名称与会话。

当前协议通过开发/组织私有插件能力取得真实 `fileKey`。开发插件从官方桌面版导入；在内嵌 Web 编辑器内运行同协议，需要符合 Figma 的组织私有插件条件。普通 Community 发布不能自动替代这项能力。网页登录、文件能打开和插件已接通是三种状态；只看到文件页面还不能让 AI 写入。

插件 token 只保存在插件 clientStorage，本机服务持久化其哈希；工作区不会取得 token。重开插件会建立新会话。原会话离线时，工作区不会静默切到另一个会话，需要显式选择新的在线会话。

## 3. 先做一项可撤销的验证

选择测试文件内一个文字图层，点击 M0 底部 **操作选区**。修改文字或填充颜色，等待“已收到插件真实执行回执”，再在 Figma 原稿中检查。尺寸操作可用于支持调整尺寸的节点。

按钮按打开面板时的项目、文件、插件会话、选区版本和节点 ID 执行。选区变化后旧面板会禁止继续操作，需要重新打开。HTTP 202 仅表示入队；超时、断线和失败都不能当成修改成功。Figma 原生撤销可撤回已执行操作。

**取消**可以阻止尚未派发的命令；已经进入 Figma Plugin API 的调用不保证能即时中断。请结合原稿与迟到回执确认结果，避免在状态未知时反复发送同一条修改。

## 4. 接入聊天与多 Agent

1. 在“本地设置”选择真实模型服务，填写地址、模型名与自己的访问密钥，先测试连接。
2. 需要 AI 改图时，单独启用 **允许 AI 修改当前 Figma 文件**。默认关闭；它与本地文件写入开关独立。明确的手动操作按钮不依赖 AI 开关。
3. 保持 Design 中当前目标文件的 Bridge 在线、选中目标图层，然后在原 M0 聊天框发送任务，例如“把选中的标题改为‘立即参与’，颜色改为 #3366FF”。
4. 想使用多个角色时在设置启用多 Agent。规划、探索、复核角色只读；执行角色仅获得实际授权的工具。最终以插件回执和原稿变化判断完成。

本地文件助手直接调用受控工具；恢复的原 OpenCode 通过每次运行独立鉴权的 MCP 获取同一组工具。工具不会仅凭提示词中的任意 node ID 切换项目或文件。演示模式不会执行真实 AI 推理或修改。

当前提供读取上下文/节点、导出、创建 Frame/Text 和受控节点属性修改。原 M0 的内部 SceneGraph、企业组件搜索、剪贴板私有 runtime 和任意 JS 执行没有全部接回。

## 5. 导出与原 KRN 生成

- **操作选区 → 导出真实 JSON / SVG**：选择单个节点或画板，等待实际导出回执后下载。
- **生成原 KRN 代码**：选择一个图层/画板，服务等待插件导出真实 M0Schema，再调用恢复的原 KRN 转换器，把文件和素材写入当前项目的新 `generated/figma-…/` 目录，不覆盖已有代码。面板显示真实返回目录和结果包。

简单 View/Text 尽量保留结构；复杂矢量、旋转、混合文字、图片和效果等子树可能以 Figma 实际导出的 PNG 保留外观，`metadata.notes` 会说明。生成结果不是完整 Figma 组件、约束和实例 overrides 的可逆转换。KRN 是 React Native 源码，需要目标工程的组件依赖；Code 的 HTML 预览不能直接运行它。

JSON/Schema 单次导出上限 3 MB，PNG/SVG 单次 2 MB，选区最多同步 100 个节点。复杂文件请缩小导出目标。

## 验证范围

| 层次 | 能证明什么 | 不能据此声称什么 |
| --- | --- | --- |
| 官方网页与 native host GUI | 实际官方页面加载、导航、原生容器边界、弹窗/切页隐藏与 Code 互斥 | 不自动证明已登录、有文件权限或插件接通 |
| 插件 UI + 本机 HTTP + Plugin VM fixture | 真实配对/排队/轮询/回执脚本、scope 与权限检查、标准节点操作逻辑 | fixture 的 Figma 节点由测试环境提供，不是用户账号中的原稿 |
| 原 OpenCode + 鉴权 MCP + 上述 fixture | 恢复引擎实际发现 Figma 工具并经 Bridge 收到执行结果 | 不代表真实外部模型或用户文件已完成联调 |
| 用户账号与真实目标文件 | 按上面的手动步骤检查原稿变化、撤销、导出和代码落盘 | 只有实际完成的步骤才可标记验收成功 |

当前工程不把 fixture 测试当作真实账号端到端通过。GUI 与协议诊断保存在 `diagnostics/`，实际用户文件配对、编辑和导出仍需在正常授权的目标文件中验收。

## 常见情况

- **页面能打开，Bridge 未连接**：检查同一个文件是否正在运行插件、本机地址/端口是否一致，以及配对码是否过期。登录不会自动安装或启动插件。
- **没有 fileKey / 私有插件能力不可用**：按当前开发/组织私有插件运行条件处理，不能用伪造 fileKey 强行连接。
- **会话或选区已改变**：回到目标文件重新确认图层，选择正确的在线会话，关闭再打开操作面板；不要把原请求自动迁移到别的文件。
- **模型只分析、不改图**：检查真实模型模式、工具调用支持、AI Figma 写入开关和 Bridge 在线状态。演示回复会明确标记。
- **原 KRN 生成失败**：先检查插件能否导出该节点及素材，再看错误回执；可缩小目标。缺失素材或未确认的导出不会被当成生成成功。

旧独立本地画布和 `canvas.json` 数据保留在原路径，可独立访问；它不再是 Design 默认入口，也不会被用于伪装真实文件修改。
