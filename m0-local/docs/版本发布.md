# 版本发布说明

M0 的正式位置是 [jinny-wj/astrix-agent 的 m0-local](https://github.com/jinny-wj/astrix-agent/tree/main/m0-local)。M0 的代码、记录与发布使用独立命名空间，保留 Astrix 原有客户端、网页端和发布入口。

本工程从 **0.6.0** 开始保存应用源码。0.1.0～0.5.0 只留下阶段文档和验证证据，没有完整源码快照。六阶段导入关系保存在[历史导入映射](历史导入映射.json)，不移动既有标签，也不把当前代码改版号伪造旧版。

Astrix 客户端安装包请使用[原预览版固定入口](https://github.com/jinny-wj/astrix-agent/releases/tag/v0.1.0-preview.20260906)。发布工具虽显式传入 `--latest=false`，GitHub 当前的 Latest / `releases/latest` 仍会指向 M0 正式源码记录；这不代表新的 Astrix 安装包。[GitHub 的 latest API 说明](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)不将预发布版本作为 latest 候选。不能仅凭创建参数声称原来的 latest 入口保持不变。

## 标签和分发位置

| 标签 | 内容 | 分发规则 |
| --- | --- | --- |
| `m0/history/v0.1.0`～`m0/history/v0.5.0` | 按阶段导入的历史文档与证据 | `documentation-only`，不是可运行旧版源码 |
| `m0/v0.6.0` | 保留的首个应用源码版本 | 生成分发资源按仓库规则排除，旧标签不移动 |
| `m0/v0.6.2` 及后续 `m0/v版本号` | 对应版本的源码、依赖清单与文档 | 公开 Release 仅发布源码和文档，显式使用 `--latest=false` |
| `m0-runtime/v0.6.2` 及后续 `m0-runtime/v版本号` | 生成资源和恢复运行组件 | 受限草稿；不放到公开 M0 Release 或普通 Git |

M0 不复用 Astrix 的普通版本标签和预览标签。GitHub 为历史标签自动生成的源码压缩包，不代表当年完整源码；如创建历史 Release，标题和正文必须明确“仅历史文档，无源码快照”，并保留独立命名空间。

版本清单保存在 [versions/index.json](../versions/index.json)，单版记录保存在 `versions/v版本号.md`，变化总表为 [CHANGELOG.md](../CHANGELOG.md)。旧私有仓库 `jinny-wj/m0-local` 的 0.6.0 发布摘要继续保留为来源证据；其中仓库、可见性与附件字段是旧记录，不是当前正式发布位置。

每版可上传的验证摘要保存在 `versions/evidence/v版本号.json`，只包含来源文件相对路径、字节数、SHA-256、白名单结果和限制。原始 `diagnostics/` 不上传 Git；摘要不复制日志正文、个人路径、凭据、项目或会话数据。来源哈希不表示本地原始文件已经公开。

## 发布命令

在 Astrix 仓库内进入 M0 目录：

```sh
cd astrix-agent/m0-local
npm run release
```

默认只校验版本、记录、命名空间、Git 目标与待提交内容，不提交、不建标签、不推送，也不创建 Release。应先准备好本版代码和版本文档，并按[运行包说明](GitHub运行包.md)准备运行资源。

```sh
npm run release -- --publish
```

正式源码发布执行必要测试、提交本版改动、建立 `m0/v版本号` 标签、推送提交与标签，并创建对应的源码 Release。该 Release 使用 `--latest=false`，不携带生成前端、生成器、图标或恢复引擎附件。既有标签不变，代码调整后应递增版本。

需要准备受限运行资源时使用：

```sh
npm run release:runtime
```

归档输出到被 Git 忽略的 `.release-assets/`。资源只按[运行包说明](GitHub运行包.md)的受限草稿流程分发，不能顺手上传到公开 `m0/v版本号`。受限草稿也不携带用户账号、项目或会话。公开源码包不是完整运行安装器。

## 每次升级的流程

1. 在 `astrix-agent/m0-local` 完成代码和必要验证，区分真实界面/服务、本机测试模型与模拟节点，记录本次实际结果。
2. 同步 M0 的 `package.json`、`package-lock.json`、服务版本号、`CHANGELOG.md` 和 `versions/index.json`，新增 `versions/v版本号.md`。
3. 核对待提交内容只属于本次 M0 变更，保留 Astrix 其他项目和根发布配置。生成资源、安装器、恢复运行组件、个人配置、凭据、Figma 登录、配对令牌、项目和会话均留在 Git 之外。
4. 校验 `origin` 指向已确认的 Astrix 仓库，先获取远端变化，再用源码发布流程建立准确提交和 `m0/v版本号` 标签。不得强推或移动旧标签。
5. 如需运行资源，单独生成并验证，保存在同版本受限草稿 `m0-runtime/v版本号`；公开源码 Release 只说明准备方式，不公开这些附件。
6. 核对远端提交、命名空间标签、Release、版本记录一致，确认 Astrix 原有预览标签、Release 和附件保持原样，并提供本次源码版本链接。

新克隆的应用目录为 `astrix-agent/m0-local`，原引擎恢复包应解压为 `astrix-agent/M0-AI-recovered`。资源准备范围、平台和访问要求见[运行包说明](GitHub运行包.md)。
