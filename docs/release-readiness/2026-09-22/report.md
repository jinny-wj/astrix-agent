## 必须处理的发布阻断

### 1. 客户端当前只能作为本机测试包

直接对已安装应用执行发行检查，Gatekeeper 返回 rejected，公证校验明确没有票据。把当前应用或重新压缩出的 DMG 发给用户，不会因此获得正式发行资格。

当前发行预检也因缺少开发者发行证书失败。需要有效 Developer ID 签名、Apple 公证、附加公证票据，再对最终下载产物验收。Apple 的直接发行流程见[官方说明](https://developer.apple.com/developer-id/)。

仓库的正式发行脚本要求 universal；当前应用只有 arm64。若决定只支持 Apple Silicon，应明确产品支持范围并相应调整发行验收规则，而不是把 arm64 包称为所有 Mac 通用版。

### 2. Agent 入口缺少有效的访问控制，不能原样暴露公网

在独立临时工作区、随机本机端口中，对两端分别发送来自非受信网页的 text/plain 上传请求，没有提供登录会话。**两端都返回 200，且确实写入了测试附件。** 本次未调用模型，也未访问真实设计文件。

原因：Agent 中间件设置了部分跨域响应头，但入口没有真正拒绝非受信来源，也没有把上传、对话与登录用户绑定；请求体解析不要求 JSON 内容类型。跨域响应头不能代替访问控制。

来源：[客户端入口](../../../客户端/server/agentPlugin.ts)、[网页版入口](../../../网页端/server/agentPlugin.ts)。

此外，两端的 Claude 运行器允许 Bash 并跳过工具权限确认。公网匿名入口与这种运行权限结合是严重风险；仅在提示词中要求“不修改文件”不是隔离措施。本次未执行攻击性模型请求，实际远程命令利用链未经验证。

发布前需要：服务端强制认证和权限检查、请求来源及内容类型校验、请求大小/并发/调用限额、按任务隔离运行环境，以及可执行工具的明确授权边界。桌面端的回环地址与 Host 校验可以限制部分网络访问，但不能代替这些入口检查。

### 3. Bridge 与附件没有面向多用户的所有权隔离

隔离测试中，没有登录也能发布 Bridge 测试会话，并读取该会话信息；两端均返回 200。附件校验接受共享附件目录中的现有路径，没有用户所有权参数。

当前文件标识、会话标识和选区版本主要用于避免误改图层，不能当作用户权限。公网上线前应把用户、任务、上传文件、Bridge 连接与设计文件权限绑定；排队、拉取、回执和状态查询都需要校验归属。

来源：[Bridge 中间件](../../../网页端/server/figmaBridgePlugin.ts)、[附件校验](../../../网页端/server/agent/composer.ts)。

### 4. 网页版尚无完整公网生产运行方案

当前只有 Vite 开发、构建与预览命令，没有独立生产后端启动入口；Agent、授权、Bridge 等依赖 Vite 插件提供服务。只部署 dist 会缺少这些能力；使用 Vite 开发服务器对外服务也不能补齐上述安全要求。[Vite 官方明确说明 preview 不是生产服务器](https://vite.dev/guide/static-deploy)。

浏览器扩展、Bridge 插件及默认授权回调仍面向本机地址。需要明确网站后端与用户本机 Agent/插件的连接方式，配置域名、HTTPS、授权回调、受认证的 Bridge 通道、进程管理、存储与恢复方案。不能只把监听地址改成公网地址。

本次没有获得目标域名或服务器信息，因此未验证真实 HTTPS、代理、DNS、备份、监控和线上回滚。

## 其他上线前问题

- **依赖公告**：生产依赖检查中，客户端发现 4 项高、9 项中、1 项低级别公告；网页版发现 4 项高、8 项中、1 项低级别公告。高等级结果均涉及 fast-uri 3.1.5；还涉及 hono、qs，客户端另有 uuid。应升级受影响依赖并验证兼容性。公告命中不等于应用已被证明可利用，具体调用路径尚需评估。详情及公告链接保存在 evidence.json。
- **两端功能不一致**：图片/H5 调整面板和解析器只在客户端，网页版未包含上一轮新增能力；双端发布前需要同步实现与测试。
- **新用户初始化门槛**：客户端当前依赖用户配置 Figma 应用连接信息，以及安装、登录可用的 Agent 后端。随包配置未包含本机登录数据，这是正确的，但新电脑不会继承开发机的使用条件。必须验收未装 Node、未装 Agent、未配置 Figma 的首次安装流程，并清楚说明需要用户完成的步骤。
- **启动等待体验**：本次最终进入首页，但启动仍同步等待安全存储读取完成，未见超时后恢复入口；需要覆盖拒绝、取消、持续等待和升级后再次授权场景，不能保证陌生电脑无阻塞。
- **Figma 插件发行**：目前是需要导入的开发插件，且开启了 Private Plugin API；需要明确实际可分发方式和用户安装路径。真正的文件读取、选区同步、图片/H5 修改、失败回执与升级后的插件兼容性仍未在真实文件中验收。
- **可复现安装**：两端缺少明确的包管理器版本约束。当前环境的网页版常规命令触发依赖准备并因安装脚本策略失败；发布流水线应固定 Node/包管理器版本、依赖锁与必要的构建脚本许可。本次没有批准额外安装脚本，自动生成的占位配置已移出源码目录。

## 建议的处理与验收顺序

1. 先修复 Agent 和 Bridge 的认证、权限、所有权与执行隔离，建立独立生产后端。
2. 同步双端能力，固定可复现构建环境，修复并复查依赖公告。
3. 完成面向普通用户的 Figma/Agent 初始化流程及启动恢复。
4. 配齐 Apple 发行条件，生成并验收最终签名公证产物。
5. 在干净 Mac 上从下载、安装、授权、实际修改到升级完整走通；在隔离预发布环境用两个不同用户验证权限隔离、限额、断线恢复及回滚。
