# 需求澄清与任务续接

客户端和网页端在本机保存会话。缺少关键信息时，任务进入“等待补充”，原需求、已确认的回答、附件及目标上下文不会因本轮回复结束而丢失。

## 使用

1. 在项目中描述任务并附上素材，Figma 操作还需连接目标文件并选择图层。
2. 如缺少关键输入，助手显示问题卡片。可以填写卡片后点“补充并继续”，也可以在同一聊天中直接回答。
3. 后台将回答合并回原任务，重新检查剩余缺项；齐全后才进入执行。必要时继续追问，不能把第一条回答自动当作所有问题均已解决。
4. 刷新页面会恢复该会话和待回答问题。客户端、网页端分别保存自己的会话，不会自动共享账号或任务数据。
5. 需要换一个任务时使用“新任务”；不再执行当前任务时使用“取消”。已进入工具执行的操作可能已产生实际结果，取消不会伪称撤销已有结果。

未选择或配置模型时，只保存需求和可检查的输入；需要模型的语义判断与执行保持待运行。明确、不依赖模型的受支持 Figma 属性操作仍需通过选区、指令和 Bridge 校验。不能把“输入已保存”当作“设计修改完成”。

## 上下文与执行边界

- 保留原始需求、历次问题和回答、所选 Skill、附件、引用、附加指令及当前任务的 Figma 目标。
- 回答不会作为一个孤立的新任务重新选择 Skill。后续补充素材与原素材一起保留。
- 选区或文件变化会阻止旧目标继续执行，或要求明确确认新目标；不会静默改向另一份设计稿。
- 执行前的语义预检没有执行工具，必须返回有效的“信息齐全／需要追问”结构。格式错误、取消或校验失败时不进入执行。
- 请求标识用于识别重试；同一会话不并发执行两个回答。执行结果不确定时不自动重复工具操作。
- Figma 成功仍以目标文件插件的真实成功回执为准。

## 实现入口

默认工作台由两端共用 `网页端/workbench/server/chat.mjs`、`conversations.mjs` 和 `frontend-tools/clarification-monitor.js`。原设计界面由两端各自的 `server/agent/conversation.ts`、`server/agentPlugin.ts` 和 `src/components/editor/agent/ConversationFlow.tsx` 接入。

默认工作台使用项目会话 `sessionId`，原设计界面使用独立 `conversationId`。各自的后端保存完整任务数据；浏览器只保存恢复会话所需的标识。

已有工作台运行资源可增量更新本次本地界面脚本：

```bash
node 网页端/workbench/frontend-tools/prepare-frontend.mjs --refresh-local
```

该命令仅更新本地澄清界面并接入已还原的工作台，不读取账号、模型配置或个人项目。完整前端重建仍按原资源准备流程执行。

## 验证范围

使用临时目录和本机模拟接口验证问题暂停、结构化与普通文本回答、多次补问、原任务恢复、刷新和服务重启、附件保留、选区变更、取消、新任务、重复请求及并发隔离。真实模型未配置、未调用；真实 Figma 设计稿未用于写入验收。
