# 双端工作台版本发布

0.7.0 起，工作台的真实实现分别位于 `网页端/workbench/` 与 `客户端/workbench/`；当前共享包只保存路径、验证、版本和打包发布。两端正式入口见各自 README。

## 版本与历史

两端 package、共享 package/lock、`CHANGELOG.md` 和 `versions/index.json` 使用相同工作台版本。同步维护两端依赖锁；pnpm 锁没有应用根版本字段时不额外添加字段，也不因应用版本调整而改动依赖。单版记录为 `versions/v版本号.md`。继续使用带说明的 `m0/v版本号` 标签，不能移动或复用旧标签。

0.1～0.5 的 `m0/history/v版本号` 只有历史文档，没有对应旧源码快照；0.6.x 旧标签保留当时目录和源码。现有历史笔记只移动位置，内容不重写。[源码迁移映射](源码迁移映射.json)记录 0.7.0 的实际移动，[旧导入映射](历史导入映射.json)保留更早来源。

公开源码 Release 与资源分开：`m0/v版本号` 无附件，显式使用 `--latest=false`；`m0-runtime/v版本号` 始终为受限草稿。原 Astrix 固定预览标签和附件不受改动。GitHub 的 Latest 自动选择仍可能指向新的源码版本；它不代表新的安装器，安装试用继续使用对应固定入口。

## 校验与发布

```sh
cd packages/astrix-workbench
npm test
npm run release
```

默认发布命令只校验，不提交、推送、建标签或调用 GitHub。它核对版本、记录与待提交文件，只允许：

- 两端 `workbench/` 实现、实际 React/Vite/Electron/服务接线、构建脚本和必要的包/锁/配置。
- 共享包及本次需要的根 README、AGENTS、ignore 和指定版本 workflow。

0.7.0 的源码迁移已完成。0.7.1 起发布器移除旧应用目录的迁移白名单和删除例外，旧路径的任何变动与其他范围外文件一样被拒绝。

发布器拒绝不在明确列表中的改动、任意整个仓库发布、私密状态、本地归档、依赖、诊断、生成界面和原生资源。出现不相关改动应先处理该范围，不能把白名单改成仓库根来绕过。

准备完整后：

```sh
npm run release -- --publish
```

命令先获取远端状态，拒绝需要强推的分歧，执行测试后按白名单提交准确源码、建立 annotated 标签、推送分支与该标签，再创建源码 Release。已有源码标签不可移动；已有版本只能在同一准确提交上重试。

## 资源草稿

```sh
npm run release:resources
npm run release:runtime
```

生成资源采用布局 2，原生恢复包仍是仓库根 `M0-AI-recovered/`。输出到共享包 `.release-assets/`，不入 Git。正式发布器只将允许且同版本的归档/清单/校验文件上传到 `m0-runtime/v版本号`，逐次确认 draft 和准确目标提交；不会把草稿改为公开。

归档范围、解压位置与平台见[运行包说明](GitHub运行包.md)。即使运行资源内容没有变化，新版本仍应生成对应版本清单与校验文件，不能把旧版附件改名冒充新版。用户模型配置、项目/会话、Figma 登录、配对令牌和 Electron 用户状态都不能进入 Git 或附件；数据位置调整必须保留原内容，不能把本地归档加入发布。
