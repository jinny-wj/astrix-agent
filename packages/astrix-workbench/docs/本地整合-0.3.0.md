## 使用

打开本地项目，选择“设计”进入画布。先创建或选择 Frame，再绘制形状和文字；属性修改、拖动和尺寸调整均可撤销重做。画布自动保存到该项目的 `canvas.json`；重载可继续编辑，冲突时停止覆盖并提示重新载入。

文件菜单支持画布 JSON、M0Schema 和 Figma REST JSON 导入，以及 M0Schema、SVG 和画布 JSON 导出。图片、复杂矢量、旋转、渐变和阴影等导入会提示降级范围；当前不解析 `.fig` 二进制文件。“生成原 KRN 代码”使用已保存版本，生成 `App.tsx/styles.ts`，写入该项目全新的 `generated/canvas-时间戳/`，可查看或下载，不覆盖原有源码。React Native / 企业组件依赖仍需在目标工程提供。

Code 工具栏提供“终端”“扩展”“安装 VSIX”。终端可交互运行本机命令；VSIX 从系统文件选择器选取后，由原安装器安装到本工程独立的 editor profile，并由原扩展宿主激活。随包 JSON、HTML、CSS、Markdown、TypeScript 语言服务沿原启动链运行，外部改动由原 watcher 传回编辑器。需要额外二进制或远端服务的扩展可能仍需适配；目前不自动联网下载。

配置模型后，可以在设置里把工作流切到“多 Agent”，继续使用原聊天输入框，或从“多 Agent”入口使用独立工作台。主聊天显示实际角色进度，独立页面提供任务与运行记录。演示模式没有规划模型、子 Agent 或推理调用。文件修改沿用“允许 AI 修改当前工作区内的文件”开关；桌面用户终端与 AI 工具权限分别管理，AI 终端工具仍未启用。

## 多 Agent 的实际执行

规划器返回结构化任务与依赖，独立只读任务最多并行 2 个，同一工作区的写任务串行。每个角色收到真实任务及依赖产物，再由只读复核器检查，最后独立总结。所有角色固定使用本次捕获的项目目录、模型配置及历史；用户切换项目不会改变正在运行任务的目录。

使用原 OpenCode 时，各角色是独立的原生会话，角色提示词与权限分别配置。原 1.17.10 的 `agent.steps` 在压力测试中没有可靠限制循环，因此每次原生角色调用还经过临时本机模型网关；到达预算后不再向真实模型转发，并把未完成任务标为失败。记录同时包含预留预算与真实转发请求数。取消会传递至模型请求、活动角色和原生进程，进度流取消或异常中断也会收尾。

运行记录位于 `.local-data/workflow-runs/`，可按项目查看；项目过滤在分页之前执行。`promptSources` 记录实际提取的原提示词来源及哈希，`scheduler` 标明 `original-langgraph-local-graph`，并明确 `businessGraphReused:false`。没有执行带企业初始化的原业务 bundle。

- `diagnostics/native-editor-terminal.json`：终端/扩展 13 项全通过，包含真实 `pwd/printf`、当前目录、JSON provider、watcher、本地 VSIX 安装/激活/补全及 helper/shell 退出。
