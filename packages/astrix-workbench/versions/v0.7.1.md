# Astrix 0.7.1：清理旧应用目录与发布路径

记录日期：2026-10-25。类型：**source-release（源码发布）**。兼容标签：`m0/v0.7.1`。

本版继续使用客户端与网页端的实际入口，移除已旧的独立应用目录位置和路径回退。原有用户数据保留，工作台状态使用客户端自己的数据目录；本地备份与测试状态归档不进入 Git 或运行资源。

## 改动

- 客户端、网页端与共享包统一为 0.7.1。共享 npm 锁的根版本同步；两端 pnpm 锁没有应用根版本字段，依赖内容保持不变。
- 发布器移除 0.7.0 源码迁移使用的旧目录 pathspec、删除例外与单独 staging 分支。此后旧路径与其他不在白名单中的路径一样拒绝纳入发布。
- 当前说明改为双端真实入口和实际状态位置。REA 静态分析帮助信息使用共享目录中可执行的 `node tools/run-rea.mjs` 命令。
- 开发客户端直接使用 `客户端/workbench/.local-data` 与 `.data/<profile>`，不再探测旧工程。主持久分区改为 `astrix-workbench`，既有 Cookie 与 Storage 目录同步迁移。
- 本机旧客户端正常退出后，原项目、会话及 12 个 profile 迁入客户端，19 个持久分区目录改名；工作区中的两个旧应用目录均已移走。旧源工程改名为工作区根的 `astrix-workbench-backup`，其他残留和迁移前状态保存在忽略的 `客户端/.local-archive/`，未删除用户文件。
- 0.1.0～0.7.0 的独立版本笔记、证据和已有标签保持不动；历史来源名称和内部兼容标识继续如实保留。

## 验证与发布

[验证摘要](evidence/v0.7.1.json)记录本次定向验证与验证边界。历史测试数量不计入本版结果。

- 发布范围与版本策略定向测试 18 项通过，涵盖旧路径拒绝、本地归档排除与资源仅留草稿；Git/GitHub 操作使用测试 runner，没有实际远端写入。
- `npm run release` 默认校验通过，三包及共享锁的版本一致；两端 pnpm 依赖锁与 19 个历史版本文件逐字节保持不变，原有 9 条版本索引记录未重写。
- 发布器与 REA 脚本语法检查通过，REA 无参数帮助命令正常退出，没有执行分析或安装依赖。
- 共享 Node/画布检查 153 项、宿主策略 18 项、市场策略 3 项和导航检查 3 项通过，生成器和保留画布综合检查通过；客户端测试 102 项、桌面类型检查及布局测试 5 项通过。
- 使用独立临时状态启动当前客户端，10 项检查通过：0.7.1/desktop 身份、Astrix 标题、页面与原编辑器可用，新分区落盘且没有重新生成旧目录。应用、后台服务与临时状态正常退出清理。
- 实际迁移验证项目文件哈希、用户配置与聊天内容保持一致，项目和工作区路径有效；公开记录不包含账号、私密路径或原始诊断。

源码继续使用带说明的 `m0/v0.7.1` 标签和不带附件的公开 Release，资源沿用布局 2。对应版本的生成资源与恢复原生组件只放入受限草稿 `m0-runtime/v0.7.1`；资源清单按本版版本生成，旧版归档不改名、不覆盖。

本次没有新增产品界面功能。外部模型、Figma 账户、真实设计文件和云端协作仍需接收者完成正常配置；本版不会把旧版这些能力的测试结果当作新的端到端验收。

运行与发布见[共享说明](../README.md)、[运行包说明](../docs/GitHub运行包.md)和[版本发布流程](../docs/版本发布.md)。
