# Astrix 0.7.4：真实 Figma 插件导入与双端只读联通

记录日期：2026-10-25。类型：**source-release（源码发布）**。兼容标签：`m0/v0.7.4`。

本版完成官方 Figma 开发插件创建与导入，并在真实用户文件中将同一插件同时配对客户端和网页版。两端均实际收到选区同步与只读上下文执行回执；不以测试节点或模拟会话替代真实验收。

## 修复

- Figma 实际拒绝原 manifest 中的 IP 网络模式。改为 `allowedDomains: ["none"]`，仅在 `devAllowedDomains` 中允许指定端口的 `localhost`。插件 HTTP 传输走 localhost，已有逻辑连接标识、配对存储与回执归属保持兼容；保留 Figma 正式分配的插件 ID。
- 真实 Desktop 宿主把 main→UI 消息从官方顶层窗口转送，原来的直接 parent 检查误拒绝这些消息。保留旧 parent 兼容，仅在来源窗口为 top 且 origin 精确匹配官方域名时允许顶层转送，并校验消息及选区结构。
- 客户端、网页端、共享包及当前说明同步到0.7.4。个人插件 ID、登录状态、配对与用户文件数据均不提交或打包。

## 实际只读验收

[本版证据摘要](evidence/v0.7.4.json)保留脱敏结果，原始回执和诊断仅留在本机。

- 通过官方 New plugin 流程创建正式开发插件，再从本机正式运行目录的 manifest 导入并在已有真实文件中运行。
- 客户端与网页版均运行0.7.4，配对到同一真实文件与同一个插件会话，工作区界面实际显示 Bridge 在线及两个选中图层。
- 在官方Figma界面只切换选择，观察两端同步2→1→2个实际图层、节点身份与选区版本一致，最后恢复原来的选区。
- 两端分别通过本地队列发出一次read-context，均收到真实插件成功回执，命令ID匹配，变更节点数为0；没有发送设计稿写入命令。
- 模型仍为demo，AI Figma写入保持关闭；未配置或调用真实模型。内嵌及浏览器官方页面以现有只读方式查看，不把画布可读推断为已登录或拥有云端编辑权限。
